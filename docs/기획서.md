# 이미지 일괄 리사이즈 + 포맷 변환 도구 — 구현 스펙

> **⚠ §3 의 「기존 Astro 프로젝트에 페이지 추가」는 폐기됐다. 아래 §10 을 먼저 읽을 것.**
> 도구는 독립 저장소이고, 이 저장소가 그것이다. 나머지 결정(§4~§7)은 그대로 유효하다.

---

## 1. 무엇을 만드나

여러 장의 이미지를 **한 화면에서** 리사이즈 + 포맷 변환하고, zip으로 한 번에 내려받는 도구.

### 왜 만드나 (차별점)

기존 무료 도구들의 공통 문제:
- 리사이즈 사이트 / 변환 사이트가 **따로 나뉘어 있음** → 30장을 두 번 올려야 함
- **서버 업로드 방식** → 용량 제한(50MB 등), 장수 제한(무료 20장), 개인 사진을 남의 서버에 올려야 함
- 무료 티어 장수 제한은 물리적 한계가 아니라 **결제 유도용 벽**

이 도구는:
- **업로드 없음** — 전부 브라우저 안에서 처리, 파일이 기기 밖으로 안 나감
- **장수 제한 없음** — 하드 리밋 걸지 않음
- **리사이즈 + 변환 + 압축이 한 번에**

상단에 이 세 가지를 배지로 명시할 것: `업로드 없음 · 장수 제한 없음 · 무료`

## 2. v1 범위

### 포함

| 기능 | 상세 |
|---|---|
| 파일 입력 | 드래그&드롭 + 파일 선택 버튼 + 붙여넣기(Ctrl+V) |
| 리사이즈 | 긴 변 기준 px / 퍼센트 / 원본 유지 |
| 포맷 변환 | WebP / JPEG / PNG / 원본 유지 |
| 품질 | 슬라이더 (WebP·JPEG만 적용, 기본 0.8) |
| 진행률 | "12 / 50 처리 중" + 진행바 + **중단 버튼** |
| 결과 | 전후 용량 비교 표시 |
| 다운로드 | zip 한 번에 + 개별 다운로드 옵션 |

### 제외 (v2로)

- AVIF (브라우저 인코딩 지원 불균등, wasm 필요 → 무거움)
- 파일별 개별 설정
- 처리 전후 미리보기 비교
- 파일명 규칙 지정 (연번/접두사)

### v1 에 들어온 것 (2026-08-22 추가)

만들다 실제로 부딪혀서 앞당긴 것들이다. 위 표의 「리사이즈」 항목이 이만큼 넓어졌다.

| 기능 | 왜 |
|---|---|
| 가로×세로 입력 | 긴 변 하나로는 "본문 폭 1200" 같은 목적지를 못 정한다. 한쪽을 비우면 그쪽은 제한 없음 |
| 잘라서 채우기 (`정확히 이 크기`) | 세로·가로가 섞인 묶음을 **모두 정확히 같은 규격**으로 만들려면 자르는 수밖에 없다. 상품 썸네일이 그런 경우다. 가운데 기준, `drawImage` 9인자 |
| 확대 허용 | 위 규격 맞추기가 원본이 상자보다 작을 때 깨진다. 기본은 꺼짐 — 없는 픽셀을 지어내는 일이라 용량 줄이는 도구의 기본값이 되면 안 된다 |

"자르려면 어디를 남길지 정해야 하고 그러면 파일별 미리보기 UI 가 필요해진다" 는 것이
v2 로 미뤘던 이유였는데, **가운데 고정**으로 못박으니 그 문제가 사라졌다.
어디를 남길지 고르게 하는 것은 여전히 v2 다.

## 3. 기술 결정

### 스택

- **기존 prelaps Astro 프로젝트에 페이지 추가** (새 프로젝트 X)
- `src/pages/` 에 `.astro` 파일 하나
- **툴 로직은 바닐라 JS** — React 불필요
  - 상태가 적고 한 방향으로 흐름 (입력 → 설정 → 변환 → 다운로드)
  - 어려운 부분은 UI가 아니라 Worker/메모리/EXIF라 프레임워크가 도와줄 게 없음
  - Astro의 "JS 최소화" 철학과도 맞고 React 런타임 40KB 절약
- **스타일은 기존 툴들과 동일하게** (사이트 톤 통일. 이 페이지만 Tailwind 도입하지 말 것)

### 라이브러리

| 용도 | 선택 | 비고 |
|---|---|---|
| 이미지 처리 | **없음 (캔버스 네이티브)** | `createImageBitmap` + `OffscreenCanvas` + `convertToBlob` |
| EXIF 회전 | **없음** | `createImageBitmap(file, { imageOrientation: 'from-image' })` |
| zip | **client-zip** | ~2KB, 스트리밍. JSZip은 전체를 메모리에 올려서 병목 |

## 4. 핵심 구조

```
[메인 스레드]
  파일 수집 → 목록 렌더 → 설정값 읽기
       ↓ postMessage (한 장씩)
[Worker]
  createImageBitmap(file, { imageOrientation: 'from-image' })
       ↓
  OffscreenCanvas 에 리사이즈해서 draw
       ↓
  convertToBlob({ type, quality })
       ↓ postMessage (blob 반환)
  bitmap.close()  ← 반드시 해제
       ↓
[메인 스레드]
  blob 수집 → 진행률 갱신 → 전부 끝나면 client-zip 스트리밍 다운로드
```

### 순차 처리 필수

한꺼번에 전부 로드하면 메모리 터짐. **한 장씩** 처리하고 즉시 해제할 것:
- `bitmap.close()` 호출
- `URL.createObjectURL` 썼으면 `revokeObjectURL`
- 결과는 **blob으로만** 보관 (dataURL은 base64라 33% 더 먹음)
- 이렇게 하면 동시에 메모리에 있는 건 한 장뿐이라 장수와 무관해짐

## 5. 함정 (여기서 실수 남)

### 5-1. EXIF 회전 ★ 제일 중요

캔버스를 거치면 EXIF가 자동으로 제거되는데, **회전 정보(Orientation)까지 같이 날아가서 세로 사진이 눕는 사고**가 남. 아이폰으로 찍은 사진에서 특히 자주 발생.

```js
const bitmap = await createImageBitmap(file, { imageOrientation: 'from-image' });
```

이 옵션 하나로 해결. **반드시 세로 사진으로 테스트할 것.**

### 5-2. onDragOver에서 preventDefault

```js
dropZone.addEventListener('dragover', e => { e.preventDefault(); /* ... */ });
```

빼먹으면 드롭이 아예 안 먹음. 가장 흔한 실수.

### 5-3. PNG 품질

`convertToBlob`의 quality 옵션은 **WebP/JPEG만 적용**됨. PNG는 무손실이라 무시됨.
→ PNG 선택 시 품질 슬라이더를 비활성화할 것.

### 5-4. JPEG 투명 배경

투명 PNG → JPEG 변환 시 투명 영역이 **검게** 나옴.
→ 캔버스에 흰색으로 먼저 채우고 그 위에 draw.

### 5-5. zip 메모리 병목

순차 처리를 해도 **마지막에 zip으로 묶을 때 결과물 전부가 메모리에 있어야 함.**
→ client-zip으로 스트리밍해서 흘려보낼 것. 이게 v1의 유일한 진짜 병목.

## 6. 용량/장수 정책

**하드 리밋을 걸지 않는다.** 경쟁 사이트의 "무료 20장" 벽과 인상이 완전히 달라지는 지점.

대신:
- 100장 이상이면 **안내만** — "100장 이상은 처리에 시간이 걸릴 수 있어요"
  (금지 문구 X. 실제로 되는데 느린 것이므로 사실이기도 함)
- **진행률 + 중단 버튼** — 오래 걸려도 통제권이 있으면 이탈 안 함
- **실패해도 부분 결과 제공** — 중간에 문제 생기면 거기까지 처리된 것만이라도 다운로드

### 배포 전 실측 필수

안내 문구의 숫자는 감으로 쓰지 말고 **테스트해서 나온 값**으로 쓸 것:
- 100장 / 300장
- 20MB짜리 대용량 여러 장
- **모바일 사파리** ← 여기가 제일 잘 죽음. 반드시 실기기 테스트

## 8. 페이지 구성 (SEO)

`.astro` 파일 안에서 **툴은 인터랙티브, 설명은 정적 HTML**로.
Astro는 빌드 시 정적 HTML을 뽑으므로 설명 텍스트가 그대로 색인됨.

```
<Layout title="...">
  <h1>이미지 일괄 리사이즈 + WebP 변환</h1>
  <배지> 업로드 없음 · 장수 제한 없음 · 무료 </배지>

  <툴 UI>          ← <script>로 동작

  <section>        ← 정적 HTML, 크롤러가 읽는 부분
    왜 리사이즈와 변환을 따로 해야 했나
    WebP가 뭐고 언제 쓰나
    업로드 없이 처리된다는 것의 의미
    자주 묻는 질문
  </section>

  <관련 도구>      ← mojibake 등 기존 툴 링크
</Layout>
```

### 메타

- `<title>` — 검색어를 앞쪽에. 예: `이미지 일괄 리사이즈 + WebP 변환 - 업로드 없이 브라우저에서`
- `<meta name="description">` — "설치 없이", "무료", "장수 제한 없음"이 CTR 올림
- `<h1>` 하나, title과 일치
- canonical, OG 태그

### 배포 후

- [ ] `sitemap.xml` 에 새 페이지 추가
- [ ] 구글 서치콘솔 → URL 검사 → 색인 요청
- [ ] 네이버 서치어드바이저에도 등록
- [ ] 기존 툴 페이지 하단에 이 도구 링크 추가 (상호 링크)
      링크 텍스트에 키워드 넣기: ❌ "여기 클릭" / ⭕ "이미지 일괄 변환"

## 9. 계측

GA 이벤트로 심을 것:

| 이벤트 | 의미 |
|---|---|
| `convert_start` | 실제로 변환 버튼을 누른 횟수 ← **방문자 수보다 정확한 신호** |

들어왔는데 변환을 안 하고 나가면 → 툴/UI 문제.
방문은 적은데 다 쓰고 가면 → 유입만 늘리면 됨.

## 10. 배치 정정 (2026-08-22)

§3 과 §8 은 이 도구를 허브(prelaps-home)의 Astro 페이지 하나로 전제하고 쓰였다.
`prelaps-home/docs/prelaps-architecture.md`(헌법)와 대조한 결과 폐기했다. **이유 세 가지:**

- 헌법 §2/§7 — 도구는 **독립 저장소 + 자기 Worker 라우트**(`prelaps.com/imagesquish/*`)다.
  허브에 넣으면 배포가 묶여서 툴 한 줄 고칠 때마다 허브 전체를 다시 올려야 한다.
- 헌법 §5 「URL 규칙: 도구 우선」 — 허브 안에 넣으면 주소가 `/ko/imagesquish` 꼴(언어 우선)이
  된다. 규칙은 `/imagesquish/ko/` 다.
- 허브는 `trailingSlash: 'never'` + `build.format: 'file'` 세트라 URL 모양 자체가
  도구들(`/race/ko/`)과 다르다.

### 확정된 배치

```
prelaps.com/imagesquish/        통로. Accept-Language 302, no-store
                                sitemap 제외 · canonical 없음 · hreflang 이 안 가리킴
prelaps.com/imagesquish/ko/     자기 자신 canonical
prelaps.com/imagesquish/en/     x-default 가 여기를 가리킨다
```

`ja` 는 나중에 붙인다. 붙일 때 **worker 의 `LANGS` · 각 페이지의 hreflang 전체 목록 ·
sitemap 을 같이** 움직인다. `LANGS` 에만 먼저 적으면 없는 폴더로 302 를 보내
일본어 브라우저 방문자가 전원 404 를 맞는다.

**출시는 ko + en 동시.** `x-default` 가 영어라 영어판 없이는 hreflang 자체를 걸 수 없고,
루트 302 의 폴백도 영어라 en 이 없으면 그 분기가 거짓말이 된다.

### 스택: Astro 아님 — 빌드 없는 정적 HTML

헌법 §4 표는 "이후 도구 = Astro" 지만, 실제로 굴러가는 두 도구(mojibake, race)는 둘 다
빌드 없는 Worker + Static Assets 다. 이 도구도 그쪽을 따른다 — §3 이 이미 "바닐라 JS,
React 불필요" 로 정했고 페이지가 언어당 하나라 Astro 가 벌어줄 게 없다.
`race` 저장소를 복사해 `PREFIX` 만 바꾼 구조다.

번들러가 없으므로 **client-zip 은 `site/vendor/` 에 벤더링**한다(race 가 three.js 를
그렇게 넣어 뒀다). CDN import 는 쓰지 않는다 — 외부 호스트 의존은 차단 환경에서 죽고,
「업로드 없음」 배지와 인상도 어긋난다.

### 이 배치 때문에 새로 생기는 함정 (§5 에 추가)

**10-1. Web Worker 경로 ★**

문서는 `/imagesquish/ko/` 에 있고 스크립트는 `/imagesquish/src/` 에 있다.
`new Worker()` 의 문자열 인자는 **문서 기준**으로 풀리므로 `'./squish.worker.js'` 는
`/imagesquish/ko/squish.worker.js` 를 찾아 404 가 난다. 반드시:

```js
new Worker(new URL('./squish.worker.js', import.meta.url), { type: 'module' })
```

언어판마다 문서 위치가 달라서, 잘못 쓰면 **한 언어에서만 조용히 깨지는** 형태로 나온다.

**10-2. 절대 경로 금지**

`/styles.css` 는 도메인 루트로 풀려 허브를 친다. 도구 안은 전부 `../styles.css`,
`../src/main.js`. 반대로 **허브 정책으로 나가는 푸터 링크는 `/ko/privacy#imagesquish`
절대 경로가 맞다** — 그건 도구 밖이다.

**10-3. GA 는 HTML 에 넣지 않는다**

도구 Worker 가 `</head>` 에 스니펫을 끼운다(`worker/index.js`, `G-NQ5XY9JPJ4` 단일 속성).
페이지 JS 는 `gtag('event', 'convert_start', …)` 만 부른다. HTML 마다 붙이면 언어판을
늘릴 때 조용히 빠뜨리고, 빠진 건 화면에 표시가 없어 눈으로 못 잡는다.
§9 의 이벤트는 이 방식으로 심는다.

**10-4. 자산 층 리다이렉트의 Location 에 접두사 재부착**

`worker/index.js` 에 들어 있다. 빠지면 `/imagesquish/ko/index.html` 의 Location 이
`/ko/` 로 나가 허브로 튕긴다 — 홈 버튼 한 번에 터진다.

**10-5. OffscreenCanvas 폴백**

§6 이 "모바일 사파리에서 제일 잘 죽는다" 고 짚었는데 대책이 실기기 테스트뿐이었다.
Worker 안에 `OffscreenCanvas` 가 없으면 메인 스레드 `<canvas>` + `toBlob()` 으로
떨어지는 경로를 처음부터 넣는다. `imageOrientation: 'from-image'` 도 실제 세로 사진으로
사파리에서 확인한다.

### §8 배포 후 체크리스트 교체

기획서의 "서치콘솔 색인 요청 / 네이버 등록" 은 **불필요**하다 (헌법 §7 「검색엔진: 아무것도
안 한다」). 하위 경로는 전부 같은 사이트라 재등록이 없다. 대신:

```
도구 저장소
```
